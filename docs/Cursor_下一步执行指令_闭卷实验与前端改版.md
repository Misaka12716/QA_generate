## 4. M0：修正身份、模式和评分契约

### 4.1 预测与审核身份

检查 `reviewing/identity.py`、`service.py`、`experiments/exploratory_review.py`：当前预测装配使用 `answer_text`，而审核对象哈希只包含 `answer`。统一规范化正文，升级缓存 schema/version；同一 subject ID 更换回答后必须触发新审核。

区分：学生输入身份、预测身份、审核身份。审核还应绑定参考答案/要点、rubric、policy、教师、提示词和证据快照。改参考标注只失效对应审核，不无谓重做未变的学生推理。聚合按完整身份关联，不能只取同 ID 的最后一条记录。

实际发给教师的请求必须包含 task_mode、condition_id、required_points、unavailable_points；明确 reference-free 与 reference-based 模式。补引用定位与声明支持校验。不能把非空引用列表当作已验证证据。

### 4.2 闭卷模式统一

检查：

- `adapters/zhixun.py::build_messages`：现有闭卷分支按 `goal=closed_book_domain`。
- `experiments/sft.py::eval_messages`：现有逻辑仅识别 `task_mode=closed_book` 或特定 context_key。
- `experiments/adapter_eval.py::canonical_messages`：已有 messages 可能绕过模式构造。

规范值统一为 `closed_book_domain`；旧 `closed_book`、`goal` 等通过兼容层映射。显式 messages 和声明模式冲突应拒绝并给出错误，而不是静默降级。

闭卷训练和推理：system 为闭卷任务政策，user 为问题；来源、gold、评分要点、旧检索历史与缓存答案均不得进入学生输入。训练只有最后的 assistant 目标参与监督。审核教师可以访问后台来源，但相应引用使用 `source_evidence_refs`。

闭卷 context 为空是正常状态，不能套用 RAG “没有材料便应拒答”的评判。闭卷模型不能静默回退到 RAG adapter。

### 4.3 历史评分兼容

当前 result_report 的 rank 为任务完成、行为适当、accept 三项相加；保留旧结果的 `legacy_rank` 与 rubric-v1 标记。新结果按事实、必要要点、行为及证据分别判断，并给出错转对、对转错、两者正确、两者错误、未决。

不得把旧“持平”映射为“两者正确”。同一个比较中的两边使用共同可判定集合，并同时展示计划分母和覆盖。旧值无法推导的新维度用 null / unavailable。

先完成 `/results` 的效果对比工作区，保留旧入口兼容。尚未接入的其他工作区显示明确空态与说明；不能放置点击无反应或假装成功的按钮。

### 5.3 效果对比页面的阅读顺序

1. 一句真实结论与限制标签。
2. 计划数、有效配对、改善/退化等关键数字，最多四个摘要块。
3. 按评测子集的共享刻度水平条形图，明确单位和分母。
4. 问题文本列表与并排回答；case ID 为次要信息。
5. 可展开的学生可见资料 / 教师后台评分依据、事实点和审核理由。

当前数据按原口径显示：历史 10 持平/4 未决，B 小试 8 持平、父协议执行 8/48。用这些记录验证首屏，不能预填任何闭卷提升百分比。

### 5.4 三个必须实现的阅读动作

- 从“未决 4”进入对应未决案例，看到具体缺失/弃权状态；若原始案例未取得，展示“仅有汇总，案例产物缺失”。
- 从问题进入 base/adapter 双回答，再展开证据与裁判理由；长回答可折叠，完整文本可复制。
- 切到闭卷模式，看该模式真实结果或空态；不得残留前一个 RAG 批次的图表数值。

### 5.5 响应式与状态

至少检查 1440、1024、768、390px 宽度。桌面双列回答，窄屏上下堆叠；导航可展开收起。禁止整页横向溢出，大表仅自身容器横向滚动。

loading 用局部加载反馈；error 有具体错误与重试；empty 不用全零图表；partial 显示已完成与计划范围；历史缺事件显示“未记录”。保留键盘可操作性、清楚的焦点、可访问名称和减少动效设置。状态以文字配颜色表达。

## 6. M2/M3：闭卷实验的具体执行要求

### 6.1 数据与协议

建立 `knowledge_id`、`source_family_id`、来源版本、训练 QA 与评测 QA 的身份和暴露关系。对历史合格池逐条检查闭卷问题是否完整明确，不能简单删 context 批量转训练。

区分四类：

| 子集 | 数据约定 | 用途 |
| --- | --- | --- |
| CB-memory | 实际训练 QA 原题 | 学习诊断 |
| CB-paraphrase | 同一训练知识的新问法，问法未训练 | 首轮主评测 |
| CB-composition | 所需事实均训练，新组合未训练 | 后续扩展 |
| CB-retention | 不进入本轮训练的固定通用/原有能力题 | 检查退化 |

独立来源评测仍保持来源族隔离。CB-paraphrase 有意测已训练知识，应显式允许该协议的事实重叠，但严禁测试 QA 被消费；不能为此关闭全局泄漏检查。完全未训练、未检索的新事实不属于本轮知识学习成功的验收对象。

### 6.2 首轮规模与对照

首轮训练最多 100 条接受的闭卷 QA；按预先固定规则选实际训练覆盖的 10 个知识单元，各 2 个新问法，得到 20 个 CB-paraphrase 输入；再加 20 个冻结 CB-retention 输入，共 40 个输入，base/adapter 合计 80 份预测。数量不足如实记录。CB-memory 另列诊断与预算。

在看本轮回答前冻结训练清单、问法、必要答案要点、保留题、教师 rubric 和模型配置。不要只选 base 答错题作为唯一测试。base 原本答对或答错的子集分析可以报告，但全体结果必须保留。

模型对照为 CB-Base 与新 CB-SFT；保持基座、tokenizer、chat template、闭卷 system policy、输入、截断与解码参数一致，仅 adapter 不同。先做单 seed，生成可复现 manifest，检查实际训练消费与 assistant loss mask。

流程依次为：协议与数据校验 → base 预测 → 训练 → adapter 预测 → 匿名审核 → 成对指标 → 前端接入。不要把训练 loss 下降直接写成闭卷问答改善。

### 6.3 教师、预算与真实调用

沿用内网教师服务和现有认证配置。可以单教师探索，但必须独立标注 teacher_single、revision unknown。为闭卷使用来源校验型 rubric，检查错误事实、漏要点、数值/条件及不当拒答；不能以“没有可见上下文”为由拒绝所有闭卷答案。

先输出预算计划。40 份参考与 80 份预测单次审核理想需 120 次调用，另有训练数据审核、生成、诊断和重试。旧额度不足整轮；仅可按已授权上限执行。已验证身份匹配的缓存可复用，未知 usage 不按零计算。GPU 训练步数、设备和生成 token 上限单独记录。

若缺预算或设备，提交完整数据与协议、页面及准确的阻塞信息；不要循环重跑 Fake，也不要反复要求已经给过的教师地址。不得读取或输出密钥内容到报告。

### 6.4 报告指标

按子集和 knowledge_id/来源家族聚合：任务成功、事实点正确、两种问法联合成功、错误断言、错转对、对转错、两者正确、两者错误和未决。净改善 =（错转对 − 对转错）/ 有效配对数，同时展示有效配对/计划数。

CB-retention 单独展示总体与 base 原本答对的子集。小样本只给探索结论，不为两个变体制造独立样本数。教师指标不是人工准确率。

每个改善/退化案例必须有问题、两个完整回答、参考要点、来源、审核理由与输入身份。没有改善也要给出明确负结果及证据；不得把“未执行”显示成“没有改善”。

## 7. M4：数据流程、数据集与 Demo

### 7.1 数据与流程

实现来源、解析/切分、QA 生成、审核、选样导出、训练、评测的阶段展示。点击阶段查看该阶段真实输入/输出及中间样本。文档、chunk、QA、token 分别标单位，禁止把它们组成伪漏斗；新增变体单列。

### 7.2 双模式问答

RAG 使用问题与资料；闭卷只有问题。切换模式时清空后端上下文并重建会话，防止旧资料经聊天历史泄露。两个模型共享相同输入与参数，独立显示加载/生成/失败/完成状态、耗时和已知 token。

在线推理尚不可用时禁用生成并说明具体原因；示例回放入口必须明确标“示例”，不能自动冒充真实推理。不要在 GET 请求里触发推理，也不要为页面打开自动消耗教师额度。

## 9. 验证重点与交付格式

只增加与真实风险有关的验证：

- 预测正文/参考要求变化会失效相应审核；不同任务模式不能误命中同一缓存。
- 闭卷所有入口最终 messages 不携带来源/参考字段；别名兼容和显式 messages 冲突可检测。
- 聚合计数正确，旧“持平”保持旧含义，未决不被当作语义失败或成功。
- 页面批次/模式切换不会显示上次请求的旧数据；点击指标能够定位对应案例。
- API 缺文件、部分产物、空数据、错误响应均有真实可解释 UI；禁止生产错误自动回退 mock。
- 窄屏、键盘、长中文/长回答、loading 和失败状态可用。至少核对桌面与 390px 截图。
