|P1|5.1、5.3|单 Chunk/单连续证据与跨块多跳、表格问题不兼容|采用 ContextBundle、多段 EvidenceSpan、表头/脚注/版本保留|
|P1|5.6|生成前后重复回答、固定三次/五次采样，成本高且错误相关|保留候选答案；一次独立证据验证作为常规路径，额外验证按风险升级|

|P1|评估体系|用过滤器自己的通过率证明质量，形成循环验证|独立人工金标；同时抽检通过和拒绝样本；下游盲测决定实际收益|
|P1|数据治理|分区、来源版本、跨块拼接、敏感数据及删除链路不充分|生成前来源族分区；记录原文版本/有效期/权限；保留完整衍生血缘|
|P2|调研综述|论文结果、通用原则和本项目预测混写，部分引用错误|仅保留与决策有关且核对过的依据；其余作为候选，不用于证明本项目收益|

### 0.2 关于用户提出的四个问题

**锚点是否保留：**保留为可选规划信号，而不是所有问题必须通过的入口。传统抽取是否“旧”不是判定标准；应检验它有没有提供额外的可控覆盖，且收益是否抵偿抽取遗漏、调用和维护成本。直接根据 Chunk 生成也可以严格使用证据，并不等于无依据的 Self-Instruct。

**题型与配额：**不追求无限扩展题型，也不把类型数当成多样性。先拆分维度，再根据业务需求、来源可支持性、学生薄弱项、风险和成本形成配方，控制的是最终发布分布与实际训练 token 暴露量。

**预算：**从“便宜模型 + 缓存”升级为可执行约束。所有生成、失败重试、校验、探测、人工审核和训练评估都计费；预算不足时减少数量、延期发布或停用非必要步骤，不能降低事实和权限门槛。

**知识增益是否做：**保留无上下文测试作为低频、抽样、可缓存的诊断；取消作为全量硬过滤。已知样本可用于能力保留、表达/引用训练和抗干扰。回放是否有效、需要多少，必须由目标学生的训练对照实验决定。[R02–R04]

## 1. 文档概述

### 1.1 背景与目标

建设一条从企业来源文档到可发布训练数据的自动化管线。默认优化目标不是“生产最多 QA”，而是在质量、隐私、覆盖和预算约束下，改善目标学生在指定业务任务上的表现，并限制原有能力退化。

可保留原稿的四项目标：端到端生成、质量可审计、成本效率可测、组件可替换。删除未经压测的“日级百万 QA”“单 worker 每小时 5,000 条”和未经核算的单位成本承诺；这些只能作为附带硬件、模型、限流和审核条件的容量目标。

### 1.2 任务契约：必须先选再生成

|任务模式|训练输入|输出目标|来源材料的作用|核心评测|
|---|---|---|---|---|
|`rag_grounded`|业务规则 + Question + 实际可见 ContextBundle|依据当前授权证据回答、引用；证据不足则澄清、部分回答或说明不足|训练条件的一部分；必须保留上下文在 messages 中|答案正确、证据支持、引用完整、抗干扰、适当拒答|
|`closed_book_domain`|业务规则 + 自足 Question，不提供答案文档|回答许可范围内的稳定领域知识|只用于生成、核验和追溯，不进入学生输入|闭卷正确率、新知识学习、旧能力保留、版本混淆|

【修订设计】一期默认实现 `rag_grounded`，因为原稿主要以 RAG 场景、上下文忠实性和检索噪声为依据。`closed_book_domain` 是独立配方，不与 RAG 样本无标记混合。需要混合训练时，显式记录 `goal` 和策略指令，并单独报告两个模式的结果。

RAG 的“仅依据材料”与闭卷的“使用参数知识”可能产生不同的正确回答。例如 RAG 缺失关键证据时应说明不足，闭卷任务可能允许直接回答。二者不能在完全相同的输入下配置冲突标签。

### 1.3 范围与交付边界

一期：文档治理、单轮证据型 QA、必要的不足/澄清样本、质量验证、分布选样、SFT 导出、预算与评估接口。

二期：跨文档多跳、复杂表格、多轮对话、DPO 偏好对、训练反馈后的主动补数。图谱是可选索引，不是必建基础设施。代码生成、工具执行轨迹不纳入一期；文档内简单数值计算可以通过受限计算器验证。

训练执行不属于数据 worker 职责，但训练/评估反馈接口属于本方案范围。没有目标学生或训练反馈时，只能做数据质量和成本评估，不能证明学习收益或抗遗忘有效。

### 1.4 术语修订

|术语|定义|
|---|---|
|TaskChunk|保留原文定位、来源、版本和分区的解析片段；不是所有问题的充分上下文|
|ContextBundle|某个训练/验证实例可见的若干来源片段、表格、标题和必要上下文|
|传统锚点|实体、术语、关键词等提问提示；本身不保证答案被证据支持|
|KnowledgeUnit|带证据、主体、关系/规则、条件、例外和适用范围的可验证知识单元|
|EvidenceSpan|指向某个文档版本/块的连续原文证据；一个答案允许包含多个 span|
|上下文依赖度|同一目标学生在给定/不给定证据时的任务表现差异；不是训练增益|
|训练边际收益|使用某类样本后，下游目标表现相对于对照组的变化；需要训练实验|
|保留池|经过重新核验、具有业务或基础能力保留价值的已知样本集合|
|质量等级|在共同有效性门槛之上的置信与人工复核分层，不是错误容忍级别|

## 2. 调研依据与适用边界

### 2.1 Question 生成

保留三类可比较思路：直接基于文档生成、answer-aware/知识单元引导、结构关系引导。MixQG 涵盖 yes/no、选择、抽取、生成式答案，不能把 answer-aware 一概描述成“必须人工标注连续答案 span”。本方案允许模型提出答案要点，再由证据验证器确认。[R05]

GraphGen 为原子、聚合、多跳 QA 提供知识图谱引导范式，其主要实验是闭卷知识任务；不能据此直接推出在本项目 RAG 数据、中文长文或相同预算下必然最优。[R06]

Source2Synth 使用来源约束、任务化生成和数据整理；其三次答题过滤及特定任务剔除比例可作为实验候选，不是企业 QA 的通用最优阈值。[R07]

### 2.2 蒸馏与验证

保留响应蒸馏作为默认实现。教师输出应是最终答案、必要的简洁解释、可审计的证据/计算依据，不要求暴露模型内部隐式推理。原稿将闭源推理 API 视为原始 CoT 输出源的说法不准确；OpenAI 文档说明原始 reasoning tokens 不可见，支持的摘要也不等于原始推理链。[R12]

RAGAS 可提供相关性和忠实性评价思路；ARES 同时使用针对性评判器、人工验证数据和统计校正。ARES 的“问题能检索回原段落”是检索一致性信号，不等价于答案正确性证明。[R08、R13]

### 2.3 选择、保留与噪声鲁棒性

已有研究报告持续微调中存在遗忘，并探索高质量、多样化回放；另有闭卷研究报告新知识学习与事实幻觉的权衡。这支持“测量并防范退化”，不支持“所有已知样本都必须保留”或“所有新知识都不该学”。[R02–R04]

RAFT 的无黄金文档样本仍训练目标答案，论文明确将其解释为促使记忆，而不是拒答教学。因此本方案借鉴其干扰文档构造，但把缺证据行为训练作为独立设计。[R01]

SemDeDup 支持语义去重有助于数据效率，但其 LAION/C4 结果不能直接变成本项目“删除一半 QA 无损”的承诺。[R14]

## 3. 推荐技术路线

### 3.1 路线摘要

```text
任务契约 / 验收指标 / 预算授权
              ↓
文档解析 → 来源质量与权限治理 → 来源族分区 → 结构化切分
              ↓
ContextBundle + 可生成性画像 + 覆盖账本
              ↓
批次规划器：业务目标分布 / 覆盖缺口 / 实测合格率 / 剩余预算
              ↓
路线 D：Chunk/Bundle → Q + 候选 A + 证据
路线 K：Bundle → KnowledgeUnit → Q + 候选 A + 证据
              ↓
结构、权限、证据定位硬检查 + 早期轻量去重
              ↓
独立证据验证 → 通过 / 有界修复 / 风险升级 / 隔离
              ↓
RAG 行为构造：干扰、缺证据、冲突、澄清（按契约）→ 重新验证
              ↓
联合去重 + 实际类型复核 + 学生诊断（抽样）
              ↓
学习 / 保留 / 行为联合选样 + 最终分布核验 + 人工抽检
              ↓
DatasetVersion + SFT/DPO 导出 + 成本/质量报告
              ↓
训练评估接口 → 开发集弱项/遗忘报告 → 下一轮配方
```

预算控制、来源权限、审计、缓存、失败状态覆盖全部节点。测试集内容不得流入规划器、生成提示词或配额调优。

### 3.2 路由原则

【修订设计】优先运行直接生成基线。直接路径覆盖率不足、条件/例外遗漏多、知识单元能跨题复用、或者跨片段关联有明确收益时，启用 KnowledgeUnit 路径。规则/NER 提示可作为低成本辅助，不强制成为独立阶段。

路由依据使用可观测特征：文档结构、规则密度、证据片段数、表格比例、历史遗漏率、独立知识单元密度、生成失败原因和单位合格成本。不能仅凭“某种意图”或“模型自报难度”决定强教师路由。

没有足够路由数据时，采用按文档族分层的随机试验，为不同路径保留探索预算；不预设长期 70:30 或其他固定比例。

## 4. 输入预处理与证据管理

### 4.1 解析与来源质量

解析器沿用可插拔设计，但必须实测中文、扫描件、表格、公式和脚注质量。不能将某个解析器的名字视为正确性保证。

每份文档记录 `document_id`、`source_hash`、`source_version`、`effective_from/to`、`authority_level`、`tenant_id`、`access_scope`、`source_group`、`parse_version`。解析缺页、表格列错位、脚注丢失、版本冲突等进入隔离或人工修复队列；不静默跳过并继续声称覆盖完整。

来源证据只能说明“答案与这个授权版本一致”，不能自动证明材料本身真实、最新或适用于当前用户。权威性和有效期由业务规则配置；冲突未解决时不能让模型自行选取更熟悉的说法。

### 4.2 先分区，后生成

同一文档、修订版、镜像、相邻重叠块、同一表格衍生材料以及生成的改写/多轮/DPO 对照，都应在来源族和样本族层面保持分区一致。先建立文档近重复关系，再固定 train/dev/test；生成任务不能跨分区拼接证据。

对新文档 RAG 评测，测试时给模型该文档是任务允许的输入，不等于训练泄漏；问题在于是否曾把测试文档/答案用于合成训练、调提示词或选配额。另设“已见文档的新问题”评测并清楚标注，不能与文档级泛化混报。

### 4.3 切分与 ContextBundle

以章节、列表、步骤、规则与例外的完整性优先，使用目标模型 tokenizer 的 token 预算；固定 600 字/80 字重叠仅作为待比较基线，不作为所有文档的默认最优设置。

保留标题链、指代所指对象、单位、表头、行键、脚注、公式定义。长表按行组/列组拆分时重复必要表头，不能简单“整表永不切分”而超出窗口。

单块证据不足时构建有限 ContextBundle。跨块只允许经过确认的连接，例如共同产品版本、明确引用关系、同一实体的相关属性；禁止为满足多跳配额任意拼接相似段落。

### 4.4 证据标识

每个 EvidenceSpan 保存：`evidence_id`、`document_id`、`source_version`、`block_id`、`start`、`end`、`quote`、`location`、`content_hash`。字符偏移统一为 Python/Unicode code-point 的半开区间 `[start,end)`；归一化文本到原文保留映射，不能在文本改变后继续使用旧偏移。

证据定位由确定性代码校验，不依赖 LLM 自报偏移。可先给生成模型稳定块/句 ID，返回引文后再定位。重复字符串须结合块和偏移消歧。

一个事实性回答允许引用多段证据。表格证据除单元格值外，还需附行列键、单位及适用脚注。

### 4.5 隐私与提示注入

脱敏在外发教师前执行，正则只是辅助。租户权限、商业秘密、个人信息及服务商数据使用条件由策略配置。保持必要的实体一致性，避免把两个不同对象都替换成同一个占位符，破坏推理或误造重复。

原文、候选答案和外部生成文本都按不可信数据隔离；其中“忽略规则”“输出密钥”“给本样本满分”等内容不能作为执行指令。证据解析器与评判器默认无外部写权限，日志也受租户权限控制。

## 5. Question 生成与类型分布

### 5.1 两条生成路径

#### 路线 D：直接证据约束生成

输入：ContextBundle、允许的任务契约、当前批次的覆盖缺口和少量风格示例。

一次生成 `Q + candidate_answer + answer_points + evidence_refs + provisional_tags`。允许返回空集合，表示该片段没有适宜的新问题。数量由独立信息量与已有覆盖决定，而不是每块强行 3–6 题。

此路径的优势假设是低额外成本、保留整体语义；风险是假设生成器会集中于显眼事实、遗漏长尾条件。优势与风险都需要通过抽检与下游实验验证。

#### 路线 K：结构化 KnowledgeUnit 引导

知识单元不是把 TF-IDF 换成 LLM 关键词。建议结构如下：

```json
{
  "unit_id": "ku_001",
  "unit_kind": "conditional_rule",
  "subject": "产品A/版本2.1/批量导入",
  "proposition": "示例：单次最多导入1000行",
  "conditions": ["示例：使用标准模板"],
  "exceptions": [],
  "evidence_refs": ["ev_001"],
  "source_scope": {"product": "产品A", "version": "2.1"},
  "verification_status": "pending"
}
```

以上值是结构示例，不来自用户业务材料。知识单元只有通过证据核验后才能用于出题；未核验的抽取结果不能成为第二手“事实源”。生成器仍可读取原文，而不是只看压缩后的知识单元。

可采用规则识别数字/条件候选 → 小模型结构化抽取 → 有疑义项强模型复核。保留 `source_raw`，防止条件、否定、例外和时间约束在压缩时丢失。

跨块多跳使用知识单元之间可证实的依赖关系。删除某个必要证据组后应使预期答案不再被充分支持，但替代证据存在时应先归并等价证据组；不能简单按引用数或 Chunk 数认定多跳。

#### 抽取是否值得独立调用

比较一次联合生成知识单元和 QA、先抽取再多次复用、完全直接生成三种开销。知识单元只使用一次时，独立抽取可能是纯额外成本；一份文档用于多轮覆盖规划、多个意图或增量更新时，复用更可能有价值。这是待测的路由依据，不是预先断言。

### 5.2 正交标签体系

主意图先使用六类；它们是项目管理用的初始分类，不是宣称完备的语言学体系。每条样本有一个 `intent_primary`，必要时附 `intent_secondary[]`；以主要交付目的消歧。无法归类的有效问题进入 `other_review` 监控池，当出现稳定业务簇时再扩展分类。

|主意图|说明|生成前提|
|---|---|---|
|`lookup_explain`|事实、定义、概念、参数查询|有明确事实或定义|
|`procedure`|操作步骤、执行流程|存在完整过程及前置条件|
|`rule_decision`|资格、适用条件、边界、例外下的判断|规则、条件与例外可被核实|
|`compare_select`|比较对象、按已有标准选择|对象、维度、标准均有依据；不凭空给推荐|
|`diagnose_explain`|原因、故障定位、排查解释|来源支持因果或排查关系；不能把相关性改成因果|
|`synthesize`|范围明确的总结、跨段信息整合|有可定义的必答要点集合|

其他维度独立存储：

|维度|示例值|统计原则|
|---|---|---|
|证据操作 `operations[]`|抽取、归纳、比较、规则应用、计算、时序、组合推导|允许多标签；比例不要求相加为100%|
|证据结构 `evidence_topology`|单点、多点聚合、依赖链|多跳只属于此维度，不与事实类争配额|
|媒介 `source_modality[]`|正文、表格、图注、公式|用于模型和解析质量分层|
|证据状态 `evidence_state`|充分、部分、缺失、冲突、问题歧义|状态决定预期行为，而非默认全拒绝|
|回答行为 `expected_action`|回答、部分回答、澄清、说明证据不足|“根据材料”不是行为分类依据|
|实测难度|学生成功率、失败模式、不确定区间|没有探测数据时记 unknown|
|表述特征|术语密度、显式/隐式指代、角色、问法长度|不强制覆盖所有组合|

例如“产品A 2.1 与 2.2 在该条件下最多能导入多少行？”可以是 `compare_select` 主意图，附 `conditional`、`numeric` 操作标签，证据结构是多点聚合；只有答案确实依赖中间关系链时才标多跳。

### 5.3 配额从哪里来

【修订设计】不直接替换成另一组人为比例。配额形成遵循以下顺序：

1. **业务需求画像。** 有授权的历史工单/FAQ/脱敏查询时，用分层标注估计需求；原稿将实时日志排除在范围外，因此日志只能作为可选新增输入，不作为一期必备依赖。无日志时由业务专家给出任务权重和关键风险清单，并显式标记先验不确定性。
2. **语料可支持性。** 判断哪些文档能支持哪些意图、操作和证据结构。没有比较对象的片段不生成比较题，没有因果依据的片段不生成原因题。
3. **目标学生诊断。** 在与最终测试隔离的开发集上记录错误、引用失败、过度拒答、旧能力退化。不能只用错误率最大化；低通过率可能来自坏题、语料缺失或评判器错误。
4. **少量配方试验。** 比较自然需求分布、温和长尾补偿、弱项导向混合；保持训练 token/算力预算可比，按业务加权指标及最差关键切片表现选配方。
5. **批次反馈。** 根据过滤后的真实分布与合格率更新生成任务，冻结每个 DatasetVersion 的配方，不在同一版本中不可追溯地改变规则。

业务部署分布、期望训练分布、实际候选分布、最终发布分布和训练有效 token 分布是五个不同对象，需分别报告。训练分布可以为高风险或长尾倾斜，但要给出原因，不能用最大熵代替业务价值。

一个可执行的初始估计方式是：对已标注需求中类型`t`的计数`m_t`，结合专家先验`π_prior`作平滑：

\[
\pi_{demand,t}=\frac{m_t+\alpha\pi_{prior,t}}{M+\alpha},\quad M=\sum_t m_t.
\]

没有日志时`M=0`，它明确退化为专家先验，而不是伪装成实际业务分布。再建立由已确认弱项、高风险和长尾需求构成的`π_gap`，比较候选配方：

\[
\pi_t(\lambda)=(1-\lambda)\pi_{demand,t}+\lambda\pi_{gap,t}.
\]

`α`表示对先验的信任，`λ`表示补短板强度；候选值由开发集试验选择并受可生成性、关键能力底线和预算约束。该表达式是本项目的透明规划方法，不是从某篇论文得到的最优定理。不能把高错误率直接等同高收益，也不能在每次失败后无限提高该类型权重。

先控制主意图等少量边际分布和业务关键交叉切片，不对“意图×媒介×难度×证据状态×角色”全部组合设置硬配额，避免稀疏格子爆炸与互相矛盾的约束。若同一类型因答案更长占用更多训练token，必须同时调整或明确接受其token暴露偏差。


### 5.4 可生成性矩阵与缺口回填

对每个上下文 `c` 与题型/操作需求 `t` 记录 `eligible(c,t)`；取值为支持、不支持、待确认。仅对支持组合生成。每轮统计：

\[
\widehat P_{out}(t)=N_{accepted,t}/N_{accepted}.
\]

若目标发布量为 `N*`、主意图目标比例为 `π_t`、当前合格数为 `a_t`，下一批的基础候选需求为：

\[
d_t=\max(0,N_t^*-a_t),\qquad
n_t^{request}=\left\lceil d_t/\max(\widehat p_t,\varepsilon)\right\rceil.
\]

其中整数目标`N_t*`由`N*π_t`采用最大余数等总和保持的分配方法得到，使`ΣN_t*=N*`；`p_t` 是同一生成路线、文档类型和验证配置下的端到端合格率估计，不应把不同阶段平均通过率无条件相乘。小样本用平滑估计，预算可行性同时使用保守下界做压力测试。

实际下发量还受剩余预算、可支持来源数、每个知识单元有效变体上限约束。`p_t` 接近零时先诊断失败原因，不允许通过无限扩大候选数填满配额。

生成器的 requested 类型与复核器的 actual 类型都要保留；若有系统性类型漂移，使用 `Pr(最终类型=t且合格 | 请求类型/路线=r)` 的转移矩阵调整计划，而不是相信模型输出的自报标签。

最终选样满足主意图软区间、关键能力最低覆盖和训练 token 上限；数量不可行时输出“缺多少、缺在哪里、为什么”，不强迫生成。

### 5.5 避免模板化

以“用户要完成什么任务”为提示核心，类型作为后台约束，不把同一句“请解释X”轮换名词。示例按任务和语域轮换，并隔离示例的事实内容，避免带入材料外知识。

先覆盖不同知识单元、条件、例外、失败模式和证据操作，再考虑语句变体。只换同义词而答题要点完全相同，通常计入同一家族，不算新知识覆盖。

每批生成时提供少量“已覆盖要点”和“避免重复的意图摘要”，不塞入全量历史 QA。监控模板族占比、问题开头集中度、语义簇大小、同知识单元重复次数和真实任务贴合度；这些指标用于告警和采样，不独立决定质量。

不对每个 Chunk 强行实现全部类型。配额在文档集合/业务分层上满足，而不是每个片段满足。

### 5.6 定向变换替代全量 Evol

默认关闭固定 30% 进化。仅为明确缺口执行一次有界变换：加入原文已有条件、针对已有例外、转换为真实工作场景、组合已验证证据、压缩冗余问法。

变换后重新校验问题、答案要点、证据和类型，并记录 `parent_sample_id`、`transform_type`。变换次数不是难度。引入新的外部条件而来源没有结果规则时，不能伪装成可回答问题。

## 6. Answer 蒸馏与风险自适应验证

### 6.1 候选答案复用

生成路径可同时提出候选答案，以便立即判断问题是否有明确答案目标。候选答案不能直接当金标，但通过独立验证后可以直接作为最终答案，不再机械地重新调用教师生成同一内容。

保留两种可实验路径：`联合 Q/A → 独立证据验证` 与 `只生成 Q/要点 → 独立教师回答 → 验证`。比较标签质量、错误相关性和单位合格成本；不能把“独立回答”与“独立事实验证”混为一谈。

### 6.2 常规有效性门槛

任何可发布样本，无论 S/A 等级或学习角色，都必须经过适用于该样本的有效性检查：

|检查|验证对象|失败处理|
|---|---|---|
|结构与角色|字段、JSON、messages 角色、上下文是否存在、任务模式|有界结构修复或拒绝|
|权限与来源|租户、授权、文档有效版本、分区、衍生血缘|隔离/拒绝，不允许模型修复权限|
|证据定位|引用是否确实出现在对应文档版本|重新定位一次或隔离|
|问题有效性|问题自足、范围明确、前提有依据，答案无泄漏|修复问题或改为澄清任务|
|事实支持|每条实质主张、数值、单位、否定、条件、例外是否有足够证据|修复、升级或拒绝|
|答案覆盖|必答要点是否覆盖，是否遗漏限制条件|修复或隔离|
|行为匹配|充分证据时回答，不足/歧义时采取约定行为|修复标签或拒绝|
|重复与泄漏|与其他分区/版本/同族样本的关系|按预设分区和保留规则处理|

通过这些检查代表达到当前质量控制标准，不等于数学上保证答案真实无误。仍需独立抽检估计漏错率。

### 6.3 事实主张与要点验证

将答案分解为实质主张 `claims[]`，映射到 `evidence_refs[]`；每个主张给出 supported / contradicted / insufficient / not_applicable 状态。事实准确不能被语言流畅或长度分数补偿。

答案要点 `answer_points[]` 是候选评价框架，也必须由独立验证器确认，不能让生成模型自写一个过于宽松的标准后自己通过。

原文“最多100行”与答案“最多1000行”可能主题高度相似，但事实错误。因此 embedding 相似度只能用于候选召回、聚类或辅助识别改写，不能成为正确性通过条件。

计算类：从原文抽取数值与单位，确定运算语义，再用受限计算器/表格执行器验证结果。计算器只能证明给定运算算对了，不能证明从题目到公式的映射正确。没有可验证依据的数值问题不能获得“确定性通过”标签。

### 6.4 NLI、独立重答与多教师

NLI 在选定语言和领域的人工校准集上验证后，用于 claim–evidence 的支持性分类。保留中性/不充分状态，不把中性直接等同矛盾。长证据先定位相关完整片段；跨片段推导用合并必要证据或升级验证，避免截断造成假拒绝。

reranker 只帮助定位相关证据，不替代 NLI。模型阈值按语言、领域、媒介和风险校准，不沿用未经校准的统一 0.7/0.75。

这里的“独立验证”首先指独立请求和评判任务，而不是统计独立保证；同一模型家族即使更换提示也可能具有共同偏差。独立重答和多教师适用于证据链长、存在冲突、数值/否定敏感、不同验证器分歧、业务高风险的样本。重答时隐藏原候选答案；验证时可看候选答案与原文，但不能看生成器的自评分和说服性评价。

“多次至少一次答对”不是无条件质量保证，单次失败也不证明题目错误。多教师一致不保证正确，少数答案不同也可能是允许的同义表达。比较实质主张和证据，而不是答案两两 embedding 均值。

LLM Judge 的候选顺序随机化，隐藏模型身份，设置并列/不确定/全不合格输出。需要时复核顺序敏感性，避免长答案偏好。

### 6.5 验证调度与有界修复

常规路径：轻量结构/证据检查 → 一次独立语义验证 → 联合去重。

高风险路径：常规检查 → 针对性规则/计算检查 → 更强或不同模型复核 → 必要人工审核。

【待实验验证的初始上限】每题内容修复最多一次，升级验证最多一次；网络重试采用单独上限，不与内容修复混算。初始上限是防止预算失控的工程保护，不代表最优质量策略。

重复失败必须记录原因并隔离，不能无穷“重试直到通过”。预算不足时可以减少问题数量或暂停高成本路线；不允许跳过应做的高风险验证后照常发布。

### 6.6 解释与推理数据

事实查询默认简洁答案；步骤类给出必要步骤和条件；推导类给出可核验的证据连接或计算过程。解释长度由任务需要决定，不由“多跳”标签自动触发长 CoT。

分别保存 `final_answer` 和可选 `rationale_summary`；后者也是待核验文本。是否进入 SFT 是独立实验因素，控制额外 token 成本；不把教师可见解释当成内部真实思考过程。[R12]

## 7. RAG 行为数据：干扰、缺证据与冲突

### 7.1 通道设计

|证据情形|目标标签|构造要求|
|---|---|---|
|黄金证据齐全，带无关或相似干扰|依据有效证据回答，引用正确|干扰不能意外包含另一份正确证据或引入未处理冲突|
|关键证据部分缺失|回答可支持部分，并说明缺失项|不能补写不可支持结论|
|关键证据全部缺失|说明当前材料不足；必要时提出获取信息方式|校验实际可见上下文确实不能支持答案|
|用户参数缺失，多个条件分支可能成立|提出最少必要澄清问题|不能凭空假设用户的版本、权限或业务条件|
|旧/新版本或权威级别不同|按明确适用规则选择；规则不明则说明冲突|标明版本/日期，不能以模型记忆替代文档规则|

“错误前提”需区分可从材料纠正的前提与真正歧义，不能一律拒答。无依据不等于世界上不存在答案，只代表当前任务授权证据不足。

### 7.2 防止隐藏答案泄漏

构造缺证据训练时，教师可以在受控构造环节知道被移除的黄金证据，但学生输入必须只含实际可见 ContextBundle。验证器检查最终输入，不以原始全量来源判断它“可回答”。拒答答案不能引用被移除的文档或泄漏其具体答案。

同一问题的有证据/无证据/不同版本样本保留在同一分区和样本族。它们是有效的行为对照，不因 Question 相同被自动去重。

### 7.3 比例与评测

不固定 20% 缺证据。先依据部署检索失败类型或专家构建的风险集设候选比例，在开发集上同时考察：证据充分时的正确率、证据不足时的正确说明不足率、澄清质量、过度拒答率和冲突处理准确率。

不能通过大量无依据题让“总拒答率”变高来宣称改进。困难负例和普通随机负例分开报告。

## 8. 学生诊断、训练价值与防遗忘

### 8.1 取消“知识增益”硬闸

原稿的“无上下文正确率 < 0.3 才保留”删除。取而代之的是 `student_diagnostics` 元数据与选样策略。

使用本轮待微调学生检查点，而不是强教师来判定学生是否已经具备能力。教师会答不代表学生会答。记录检查点、提示词、解码参数、答案判定器、采样次数、分数与不确定性。

定义上下文诊断：

\[
D_i=\widehat p_{\theta_t}(correct\mid Q_i,C_i)-\widehat p_{\theta_t}(correct\mid Q_i).
\]

这里的正确性应分别报告答案内容、引用和行为契约；无上下文不能正确引用本次材料，因此不能把引用缺失机械算成内容不正确，从而人为放大差值。

**探测提示与生产提示分开。** 事实熟悉度探测使用允许调用已有知识的中性问答提示，并在有/无上下文两组保持同样提示与评分标准，只改变证据输入。不能沿用“没有提供资料就必须拒答”的严格RAG系统提示，再把模型遵守拒答规则误判为它没有相关知识。生产RAG行为则另外使用真实的“仅依据授权材料”策略测试；两种探测目的、提示版本和分数不可混报。

对无上下文也能正确的题，仍可用正确证据加干扰、移除必要证据组、适用版本变化等受控任务测试其引用和依据遵循。模型在无上下文下答对，只说明答案内容可能熟悉，不证明它能处理上述任务。构造虚拟反事实时必须明确标为假设世界/测试数据，不能将虚构事实写回真实业务知识库。


`D_i` 只是当前条件下的上下文收益信号，不是互信息，不是训练后收益，也不是样本因果价值。真正的增益是训练/选样策略对独立评测的结果，需要受控实验。

### 8.2 诊断状态与处理

|学生表现|初步解释|处理|
|---|---|---|
|无上下文弱、有上下文好|上下文利用可产生收益|作为 RAG 学习候选，但仍需质量/覆盖检查|
|两者都好|内容较熟悉|进入保留或行为训练候选；高重复低价值项可降采样|
|两者都弱，但独立证据验证为正确|可能是学生能力短板或困难任务|保留适量用于课程/能力补齐，不因学生不会而删题|
|无上下文好、有上下文差|可能是干扰、旧知识冲突、输入组织或标注问题|优先诊断；有效时用于上下文遵循/抗干扰|
|结果不稳定或样本数少|不能可靠判断|记 unknown，不强行判定已知/未知|

任何状态都可能同时具有高风险、长尾和引用训练价值；这些是独立特征，不强行互斥。

### 8.3 为什么不能用两次采样做硬决策

若每次回答以0/1判定，`k=2` 的正确率只能为0、0.5、1。阈值 `<0.3` 实际只是在保留两次都失败的题。

即便暂时假设两次独立、判定准确，0/2成功的真实成功概率的一侧95%精确上限仍为：

\[
p_U=1-0.05^{1/2}\approx0.776.
\]

所以两次都失败不足以证明模型“基本不会”。真实 LLM 采样还可能相关，重复同一低温提示得到相同答案更不能被当成独立证据。[R18]

预算有限时先对训练候选分层抽样诊断；只有高价值且决策不确定的样本追加探测。缓存以学生检查点、问题、上下文、提示、解码参数为键；学生更新后旧诊断不得无标记复用。对稳定已知性可结合少量语义等价改写，但所有改写仍属于同一家族。

### 8.4 保留池与训练暴露控制

数据按选样主角色分为 learning、retention、behavior，另保留多标签价值描述。每条样本只能按一个主角色计入混合比例，防止重复计数；高风险或引用等次标签不受此限制。

保留池包括经过核验的关键旧业务知识、核心操作、基础读题/表达/指令能力。对过期、被新规则替代的“旧知识”，应训练版本判别或移出当前知识池，而不是为了防遗忘强化错误答案。

“原本会”不是全保理由。选取高质量、有代表性、覆盖重要能力的子集，限制同知识单元的重复 token 暴露。单纯多次复制同一个 QA 不能等同于有效保留。

回放比例以训练 token 暴露量报告，同时报告样本数。可用0%、10%、20%作为第一轮待测网格；它们仅为实验候选，不是生产推荐，也不是文献给出的通用比例。具体保留需求取决于学生、领域差异、训练强度和目标能力。[R02–R04]

### 8.5 防遗忘评测与反馈

建立互不泄漏的 `retention_train`、`retention_dev`、`retention_test`。训练前测基线，训练中使用 dev，最终使用锁定 test。

报告旧能力净下降及“先前稳定正确、训练后失败”的转移率；后者的稳定正确应尽量用独立预筛或重复评估确认，避免把单次偶然答对和回归均值误判为遗忘。按领域、能力、知识类型分层，给出置信区间。

同时比较领域任务增益、旧能力退化、过度拒答、事实错误和训练成本。若回放改进旧能力但严重损害目标任务，调整配比或与训练侧协同检查学习率、步数、参数适配等因素；数据回放不是唯一可能的原因或解决办法。

## 9. 去重、质量分层与发布选样

### 9.1 两阶段去重

生成前/早期：文档族、规范化精确哈希、问题近重复召回，避免明显重复继续支付强教师费用。哈希冲突须可复核，不能仅靠弱哈希直接删除。

发布前：联合比较 `goal + question + answer_points + evidence + conditions + version`。embedding 只召回候选相似对，数值、否定、适用条件、版本与行为标签决定是否真正可互换。

对于同一知识点的少量不同真实问法可保留，用于鲁棒性；超额同义改写压缩。对比学习所需的证据变化对、版本变化对和 DPO chosen/rejected 不按一般重复删除。

### 9.2 分层规则修订

|状态/等级|含义|发布规则|
|---|---|---|
|S|共同有效性门槛通过，证据与独立校验置信充分|完成该批风险抽检与发布检查后发布|
|A|共同有效性门槛通过，语言/格式可一般，或需要补充人工确认|补充审核通过后发布；不能缺少事实支持或去重|
|B / quarantine|证据、条件、解析、判定存在未解决问题|不进入训练，只能修复后重新验证|
|rejected|无权使用、事实错误无法修复、泄漏或不适用|不发布，保留必要审计记录|

S/A 不能仅由四项均分决定。事实或证据问题不得由语言流畅补偿；“难、长、多跳”也不自动更高质量。

保留池不是低质量池。已知但重要的 S 级样本完全可以进入 retention；未知但错误的 B 级样本不能因所谓高知识增益进入训练。

### 9.3 最终选样

共同有效性门槛通过后，按业务目标、知识单元覆盖、学习/保留/行为价值、重复惩罚和 token 成本选样。初版采用透明的分层贪心和显式上下限；每个权重有来源、版本和实验记录，不用看似精确但未经验证的复杂打分隐藏主观选择。

对于一批样本集合 S，可描述为：

\[
\max_S \;\widehat U_{business}(S)+\lambda\,Coverage(S)-\mu\,Redundancy(S),
\]

约束包括事实/权限门槛、关键能力覆盖、目标分布软区间、训练 token 和费用预算。`U` 是开发集/业务先验上的估计，不声称能从单次生成分数精确识别样本训练价值。

统计 final accepted、final selected、actually trained 三个数量。有效样本被预算/去重/配额排除不是“质量失败”，须分别归因。

## 10. 全链路预算控制

### 10.1 成本口径

至少报告两种口径：`API成本/万条唯一发布样本` 与 `端到端成本/万条唯一发布样本`。后者包括预处理、索引、模型推理、失败重试、质检、学生诊断、人工审核、存储和本轮训练/评估的明确分摊。

不同模型、不同供应商按当次有效价格表与实际 usage 核算。按其计费定义区分未缓存输入、缓存输入、可见输出和计费推理 token；不能把已经计入输出的 reasoning token 再计一次。自托管按GPU时间、利用率和资源单价另计，不当成免费。

\[
C_{API}=\sum_j\frac{T^{uncached}_{in,j}p^{uncached}_j+T^{cached}_{in,j}p^{cached}_j+T^{billable}_{out,j}p^{out}_j}{10^6},
\]

\[
C_{total}=C_{API}+C_{local}+C_{parse/index}+C_{human}+C_{storage}+C_{train/eval},
\]

\[
C_{10k}=10000\times C_{total}/N_{unique,released}.
\]

当 `N_unique,released=0` 时不输出虚假的低单位成本，报告不可计算和全部已发生成本。

### 10.2 为什么原流水线昂贵

走完整普通链路的单题，可能需要出题1次、预筛回答1次、正式答案1次、Round-trip 3次、无上下文2次、Judge 1次，共约9次模型交互；还未包括进化、多教师或S级五次一致性检查。早退会减少后续调用，但丢弃样本的已发生成本仍由发布样本承担。

修订后优先：一次生成多个独立候选但限制相关性 → 候选答案复用 → 早期排除明显重复/证据定位失败 → 一次独立验证 → 仅疑难项升级 → 学生诊断分层抽样。这个缩减方案本身仍需与完整路线对照验证，不能预先保证质量无损。

### 10.3 预算对象与账本

按租户、任务、阶段、模型、批次和样本记录：

```text
budget_limit / currency / price_version
spent_settled / reserved_inflight / unbilled_reserve
stage_cap / sample_cap / max_attempts / max_output_tokens
actual_input_tokens / cached_tokens / billed_output_tokens
request_id / idempotency_key / status / cost_reason
```

调用前用事务原子预占额度：

\[
spent+reserved+unbilled+new\_reservation\leq authorized\_cap.
\]

预占依据输入长度、请求输出上限、供应商计费规则和安全余量，不仅依据历史平均值。返回后按实际 usage 结算，释放差额；超时但可能已计费的请求保留未结算预占，不能立即重试并把原请求当作零成本。

多 worker 共享同一原子预算账本；本地各自检查会导致并发超支。外部最终账单可能滞后，因此以保守预留和对账控制风险，不承诺仅凭估计绝对预测发票。

### 10.4 停止、降级和继续规则

达到总预算/阶段上限、来源可覆盖单元耗尽、连续批次边际覆盖收益过低、单位合格成本持续超标、关键切片质量未达标时，暂停相应生成路线。

允许的节流顺序：停止无明确收益的改写/进化 → 降低非关键诊断频率 → 减少可选多教师 → 优先高价值覆盖缺口 → 减少最终数量。只有经校准证明安全的低成本替代验证才能替换高成本步骤；不能关掉必需验证、降低事实门槛或自动启用 B 级补数。

保留一部分探索额度，避免完全按当前高通过率选路导致永远只生产简单题。探索比例本身是预算参数，需配方实验确定。

### 10.5 示例预算：仅演示算法，非实际供应商报价

假设首轮有20,000个候选，去重/验证后发布12,000个唯一样本；如下单价均为虚构的每候选摊销值：

|项目|数量/用量|假设单价|费用（美元）|
|---|---:|---:|---:|
|联合生成摊销|20,000候选|0.0008/候选|16|
|常规验证摊销|20,000候选|0.0005/候选|10|
|疑难升级|2,000题|0.004/题|8|
|学生探测|1,000题|0.001/题|1|
|API小计|||35|
|人工抽检|300题×45秒=3.75小时|20/小时|75|
|预处理/本地资源等|示例分摊|—|10|
|总计（不含训练评估）|||120|

由此 API 口径约29.17美元/万条，含示例人工和资源成本为100美元/万条；训练评估还需另加。这个例子说明“API便宜”不代表“端到端便宜”，不构成任何实际成本承诺。实际重试、低合格率、长答案、低GPU利用率和多标注员会显著改变结果。

### 10.6 规模与容量

吞吐由输入/输出 token 速率、API RPM/TPM、并发限制、教师响应时间、队列、验证器吞吐和人工容量共同限制。异步 Python worker 的数量不是推理吞吐的充分解释。

原稿5000条/小时/worker在24小时理想运行下为12万条/日；达到100万条/日至少需要约9个同等吞吐 worker，且仍未计限流、失败和人工瓶颈。正式SLO需在固定配置的持续压测后填写，并区分候选/验证合格/发布吞吐。

## 11. 人工校准、评估与验收

### 11.1 质量校准不能只看通过池

抽样覆盖接受、拒绝、待修复样本，分层包括文档类型、语言、主意图、证据结构、教师/验证路线和业务风险。接受池用于估计漏错，拒绝池用于估计误杀和覆盖损失。

人工金标用于校准阈值和评判器；单独保留审计测试样本，不能对同一批金标反复调参后又报告泛化质量。高风险已知错误可以作为强制回归用例，但与随机抽样的总体错误率分开。

三名标注员时采用适合多标注员的 Fleiss’ kappa 或 Krippendorff’s alpha；Cohen’s kappa 只用于明确的两人或成对分析。不仅报告相关系数，还报告误接收、误拒绝及关键错误的检出情况。

### 11.2 抽检预算与置信度

不固定“所有S抽10%、A抽30%”。初期/变更/高风险批次加密审核，稳定低风险路线按所需错误率上界设计随机抽样，并保留非零随机审计。

若独立同分布近似成立，抽检n条零错误时，一侧95%错误率上界为 `1 - 0.05^(1/n)`；约149条零错误对应2%以下的上界。它不是保证总体零错误，更不能推广到未覆盖的高风险类型。存在同文档相关性时要按来源族抽样/聚类推断，不能把高度相似题当独立样本。[R18]

整体误差率从分层样本估计时按总体层权重加权，不能把风险过采样结果直接作为总体平均。

### 11.3 指标体系

|层次|主要指标|注意事项|
|---|---|---|
|来源治理|解析完整率、未解决冲突、权限/分区错误、来源过期|权限、分区等完整性硬错误不允许发布|
|答案质量|人工事实错误率、要点覆盖、条件/例外正确、引用支持与完整性|不能用过滤器通过率代替真实质量|
|问题质量|实际可回答性/预期行为、任务贴合、歧义、答案泄漏|不足/澄清样本不是低质量题|
|覆盖多样性|加权知识单元覆盖、主意图分布偏差、模板集中度、证据操作覆盖|多样性不是单一题型熵|
|RAG行为|证据充分正确率、缺证据适当说明不足率、过度拒答、冲突处理|黄金上下文与真实检索上下文分别评测|
|学习与保留|新任务增益、旧能力净下降、正确→错误转移、最差关键切片|开发反馈与锁定测试隔离|
|成本效率|API/端到端单位发布成本、唯一知识覆盖成本、成本—效果曲线|所有失败与未发布候选计入成本|
|系统可靠性|候选/合格/发布吞吐、延迟、重试、隔离、预算超额、缓存命中|固定模型、硬件、并发和来源分布|

### 11.4 发布门槛

先检查来源、权限、分区、格式与证据可定位性；这些完整性条件要求全部满足，而不是98%即可发布。语义事实错误率、行为错误率等使用业务方批准的风险阈值和置信区间判断。

下游门槛由业务方预先定义：领域任务最小有意义改善、旧能力最大允许下降、高风险子任务最低表现和总预算。不预写“必须提升5个百分点”作为既定结论。

若数据质量合格但训练收益不显著，结论应是“可发布数据但未证明路线优于基线”；若证据不足以证明质量，继续审核或不发布，不把未知写成通过。

## 12. 实验设计（替换原 E1–E8）

### 12.1 公共实验协议

所有组共享来源分区、任务契约、评测金标、输出规范与必要安全门槛。分别报告等唯一样本数、等有效训练token/计算预算、等端到端成本三个视角；不能把“同样10K题”当成完全等预算，长解释会消耗更多训练与生成资源。

生成和训练随机性均记录。预算允许时对关键组运行多个随机种子；小样本时报告不确定性，不预设组间排序。以文档族/样本族做配对或聚类bootstrap，必要时做配对正确性检验；不能把同一知识点的几十条改写当成几十次独立证据。

采用强基线：**同样给定 Chunk、一次生成 Q/A/evidence、同样基本验证、同样任务契约**。无上下文 Self-Instruct 只作为不同来源范式的额外对照，不冒充直接文档生成基线。

### 12.2 样本规模与来源可行性

原稿500个Chunk按3–6题产生约1,500–3,000候选；若整体发布率30%，仅约450–900条。可先做这个规模的质量/成本pilot，不能凭空写成10K合格。

扩大实验应增加独立来源与可支持知识单元，或调整目标规模。不能单纯给每块重复生成几十个同义问句以满足样本数量。人工标注预算和效果检测功效按目标差异、来源族数与实际方差规划，而不固定每领域100题后宣称显著。

### 12.3 实验矩阵

|编号|优先级|问题|实验组|核心判断|
|---|---|---|---|---|
|E1|P0|双路生成是否值得|D直接生成；传统NER/TF-IDF锚点；结构化KU；混合路由|等预算下的独立知识覆盖、人工质量、下游收益、单位合格成本|
|E2|P0|类型/配额是否改善效果|自然需求分布；固定比例；可生成性+缺口反馈；加入开发集弱项|最终实际分布、模板化、关键能力、token暴露与成本|
|E3|P0|知识硬过滤是否应删除|全部有效样本；删除稳定已知；保留池回放；抽样诊断加权|新任务效果、旧能力退化、行为/引用能力、探测成本|
|E4|P0|精简验证是否足够|原固定多次验证；一次独立验证；风险自适应升级|人工误接收/误拒绝、最差切片、成本，不只看保留率|
|E5|P0|整体质量与成本可行吗|直接生成强基线；修订后的完整pipeline|等成本与等token曲线、发布质量、全链路账单|
|E6|P0（RAG）|缺证据行为是否学习到|仅充分证据；加干扰；加缺证据/澄清；加冲突|充分证据正确率与过度拒答一起看；不能只报拒答率|
|E7|P1|解释、多教师、变换的边际贡献|无解释/简洁依据；单教师/升级；无变换/缺口变换|先单因素后必要交互，分辨哪个组件有效|
|E8|P1|规模与分布鲁棒性|不同来源数量、跨文档/跨版本/跨格式、增量更新|新文档泛化、版本冲突、重复增长、吞吐与审核容量|

E3需进一步区分两种问题：固定新任务样本再额外加入回放可测“增加训练预算是否有帮助”；固定总token替换一部分新样本为回放才测“有限预算下如何配比”。两种实验都报告，不把预算增加带来的改善全归因于回放比例。

E1中直接路线也必须拿到完整同等ContextBundle；所有组后续教师/验证相同，另做端到端最优路由试验。否则比较的是上下文充分性或验证差异，不是锚点策略。

### 12.4 预注册假设与失败标准

不写“A3>A2>A1”“C3最优”“删一半无损”作为预期结论。改写为可证伪假设，例如：KU路径能否在增加的成本范围内显著降低条件遗漏；风险验证能否以更低成本达到相同漏错上界；回放能否在固定token下限制旧能力退化而不损害目标效果。

只在开发集选择配置，锁定后做一次正式测试。若批次诊断或容量不足，输出未验证项与下一步实验，而不是填造结果。

## 13. 数据模型、导出协议与任务编排

### 13.1 核心实体

沿用原稿的 TaskChunk、Sample、DatasetVersion，增加必要实体：`DocumentVersion`、`ContextBundle`、`KnowledgeUnit`、`GenerationPlan`、`ValidationResult`、`StudentProbe`、`BudgetLedger`、`PreferencePair`。

Sample必要字段如下，描述的是接口契约，不是完整可执行JSON Schema：

```text
Sample
  schema_version, sample_id, task_id, family_id, parent_sample_id
  tenant_id, access_scope, split, source_group_ids[]
  goal, policy_version, question, final_answer, rationale_summary?
  teacher_context_refs[], student_context_refs[]
  evidence[]: evidence_id, document_id, source_version, block_id,
              start, end, quote, location, content_hash
  answer_points[], claims[], claim_evidence_map[]
  intent_requested, intent_primary, intent_secondary[], operations[]
  evidence_topology, source_modality[], evidence_state, expected_action
  knowledge_unit_ids[], transform_type?, generation_route
  difficulty: proxy?, student_context_score?, student_closed_score?, uncertainty?
  student_diagnostics: checkpoint, n, prompt_version, decoding, probe_time
  selection: role, reasons[], sampling_weight, trained_token_budget
  validation: gate_results[], validator_versions[], risk_level, status
  grade, review_history[], rejection_reason?
  generation_trace: teacher_snapshot, prompt_version, parameters,
                    source_hashes[], request_ids[], cache_keys[]
  cost_trace: ledger_entries[], allocated_cost
```

无上下文任务可以有教师可见证据，但 `student_context_refs=[]`；RAG拒答任务的学生上下文可以不包含黄金证据。二者必须能从字段明确区分。

### 13.2 SFT导出

RAG样本导出必须把实际授权ContextBundle放进模型可见messages，不只放在metadata。正常RAG例子如下（内容完全为虚构演示）：

```json
{"messages":[{"role":"system","content":"仅依据提供的资料回答；资料不足时说明缺少的信息。"},{"role":"user","content":"资料[D1]：产品A 2.1版的标准模板单次最多导入1000行。\n问题：产品A 2.1版使用标准模板，一次最多导入多少行？"},{"role":"assistant","content":"一次最多导入1000行。[D1]"}],"metadata":{"goal":"rag_grounded","family_id":"demo-family-1","evidence_state":"sufficient","expected_action":"answer"}}
```

闭卷样本使用自足问题且不含资料；引用如不能由学生输入定位，不应保留伪引用标签。训练loader按当前框架明确设置assistant目标token损失、padding与截断规则，验证用户和上下文不会被误作为生成目标，也不能把末尾关键证据截掉后继续用原答案训练。

### 13.3 多轮扩展

多轮不是把多个独立QA串联。先定义用户目标、必要槽位和可见证据变化，再生成追问、澄清、用户补充与最终答复。每轮验证当时可见信息；用户模拟器不能在不自然的追问里泄漏标准答案。整段对话及其单轮派生样本同族分区。

一期不宣称已交付多轮训练数据；二期完成轮间指代、槽位、版本和每轮行为验证后再发布。

### 13.4 DPO扩展

DPO需要同一prompt条件下的偏好回答对，而不只是QA质量分。单独保存 `prompt/messages_prefix`、`chosen`、`rejected`、`preference_reason`、`judge_confidence` 和 `prompt_hash`。[R19]

两回答必须使用完全相同的可见上下文与策略；不能把有黄金证据的正确答案与无黄金证据的拒答放进同一偏好对。反例优先来自学生真实错误或受控的条件遗漏/错误引用等失败模式；不能只用明显荒谬答案训练容易区分的伪偏好。

chosen必须通过相应有效性门槛；rejected保存在专用偏好数据，不混入正向SFT。平局、事实难以区分或仅长度偏好时不强制配对。DPO增益需要独立实验，不能从SFT样本质量直接推断。

### 13.5 编排、缓存与版本

任务状态建议为 `queued → reserved → running → validated / repair_pending / escalated / quarantined → selected → release_pending → released`，错误和预算耗尽有明确终态。

幂等键包含租户、来源版本hash、配方/提示/模型版本、阶段、输入hash和预期采样seed。相同语义任务的随机多样化采样要有不同采样标识；不能被缓存折叠成同一答案。不同学生检查点、不同证据上下文和新文档版本不能错误复用旧验证结果。

DatasetVersion记录样本清单hash、所有源版本、配方、模型/验证器版本、成本汇总、抽检报告、评测状态和导出格式。保持发布快照不可变，但通过撤回/废弃标记及新版本实现治理。

来源删除/权限撤回要沿血缘禁用衍生样本、失效缓存、阻止未来发布；对已经训练的模型，删除数据文件不能保证消除其参数记忆，应标记受影响模型并由模型治理流程决定重新训练或限制使用。

## 14. 关键技术选型原则

|组件|一期建议|决定依据|
|---|---|---|
|文档解析|现有解析器保留为候选，接口可替换|按中文、表格、脚注、扫描件的校准集实测|
|切分|结构优先、token预算、必要ContextBundle|答案证据完整性与窗口成本|
|生成|直接文档Q/A为基线，KU路径可选|独立覆盖、条件遗漏、单位合格成本|
|教师|用cheap/strong/independent_validator能力角色配置|当前可用模型在项目数据上的质量、价格、权限条件|
|NLI|明确语言/任务/标签语义的已校准模型|claim级支持判别，不使用基础模型名替代测试|
|检索/向量|中文或多语embedding + 可选reranker|证据召回和重复候选搜索；不做真实性证明|
|质量判定|确定性检查 + 独立证据验证 + 风险升级|人工金标的误接收/误拒绝与成本|
|存储|关系库追溯 + 对象存储不可变快照|沿用原稿架构，不绑定特定实现框架|
|编排|队列、幂等worker、事务预算、限流/退避|可恢复性和在途调用成本可追踪|
|训练接口|messages、sample_weight/采样策略、checkpoint评估回传|实际训练token暴露和模式一致性|

不固定某个2025或2026模型名称为永久最优。模型、价格、许可证及可见推理输出能力在部署时重新核对、固定版本并纳入审计。

## 15. 风险与上线顺序

### 15.1 风险表

|风险|检测|应对|
|---|---|---|
|来源本身错误、过期或冲突|版本/有效期/权威性检查、人工来源审查|隔离、业务裁定、版本限定；不让教师自行和解|
|锚点/知识单元压缩遗漏|条件/例外金标、与原文对比|保留原文、修复抽取、改走直接路线|
|直接生成覆盖集中|知识单元覆盖与模板簇监控|按缺口补数，不盲目增大温度|
|多教师共同错误|原文证据核验、异构验证、人工抽检|一致性只作风险信号|
|过滤偏爱简单短答案|拒绝池抽检、分类型误拒绝|校准门槛、保护有效复杂样本|
|配额驱动虚构|可生成性失败、证据不足|报告配额不可行，不生造支持|
|回放强化旧错误|版本与事实复核|移除过期知识，构建版本区分样本|
|拒答过拟合|充分证据子集的过度拒答率|调整行为数据与标签，不追求总体拒答率|
|质量评测循环|独立金标与锁定测试|生成、校准、验收各自隔离|
|并发预算失控|在途预占与账单核对|共享事务账本、保守输出上限、异常熔断|
|跨租户/跨分区泄漏|输入清单、派生族、缓存键检查|发布阻断与血缘撤回|

### 15.2 上线顺序与验收物

**阶段A：契约和pilot。** 确认RAG/闭卷模式、业务验收、授权、预算，清点来源可覆盖量；建立独立金标和基线，完成直接路线与知识单元路线的小规模对比。

**阶段B：可发布单轮管线。** 上线来源分区、联合生成、证据验证、去重、预算账本和SFT导出。只在已校准范围内发布；不强制图谱、多次CoT或五次一致性。

**阶段C：分布与保留优化。** 启用实际类型反馈、长尾补数、学生抽样诊断、独立保留集和有界回放实验。

**阶段D：复杂扩展。** 在存在明确业务需求、充分证据和额外预算时加入跨文档多跳、复杂表格、多轮及DPO。

每阶段交付同一套证据：来源/样本清单、质量审计、拒绝原因分布、实际配额与token分布、总成本、下游效果及不确定区间、已知限制、可复现配方。没有这些材料不进入“百万级生产”的规模承诺。
