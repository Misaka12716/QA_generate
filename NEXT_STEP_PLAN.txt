### P0 / M0：资产盘点和可复现基线，先完成

目标：回答“代码到了哪、产物在哪、哪些步骤真正执行过、接下来缺什么”。

### P0 / M1：教师审核与审核状态改造

先实现第四节的契约、审核后端、预算、缓存和门禁；先用可控 FakeLLM 检验状态迁移，再对 batch1 的 14 题进行小范围真实试运行。

第一批真实运行默认建议上限：并发 2、调用总上限 120（含重试、复核和裁决）、单项最多 1 次技术重试、单项最多 1 次内容修订。调用总上限不是质量目标；同时配置 token 上限。美元价格未知时记 unknown，不能记为免费。

双裁判覆盖 batch1 的 14 个金标和 28 份回答至少需要 84 个单项审核调用；余量用于失败重试和有限裁决。具体预算根据模型接口长度、上下文窗口与实际计费配置确认，硬上限触发后保留未执行项，不自动放行。

验收：无需人工 CSV 就能产生可追溯的 teacher_review；同一对象重复运行可复用有效审核；任何失败、分歧或过期哈希不会自动通过；原人工审核路径及 formal 门禁回归通过。

### P0 / M2：接续诊断，默认按 batch1 → B → A 执行

1. batch1：先审核题目与金标；金标确定后再让教师查看匿名学生回答。复用旧预测的前提是完整输入与模型身份可校验。输出规则与教师的分歧表、过度拒答、证据不足仍作答、错误对象回答、部分可答处理错误及技术失败，不先训练。
2. 实验 B 优先：12 个核心问题，每组 sufficient、removed_support、wrong_object、distractor 四个条件。逐组检查移除支持后的全文是否仍有等价信息，错对象名称是否可见，干扰条件是否保留原支持；不能只用关键词删除来证明资料不足。审完整组后冻结，针对 base 与旧 adapter 做成对推理与匿名评估。
3. 实验 A：保持 system、上下文和答案需求固定，只改变问题表述。核对全部 30 组的语义、数字、对象、条件及否定词；每组原题与两条改写成组审核。补齐缺失预测，报告原题/改写分别表现及核心问题内的一致性。
4. A、B 各自是独立批次，可以分别通过门禁；某个批次未就绪不阻塞其他已就绪批次。批次内部不得静默删掉审核失败用例。修复后生成新协议版本；仍无法就绪则保留原计划分母并标 blocked/incomplete。需要改变实验规模时必须创建新协议版本并记录原因，不覆盖旧计划。
5. 评测版本全部标记 exploratory_teacher_reviewed 或 diagnostic_teacher_reviewed；不把 A 称为独立泛化，B 来自 dev，也不能冒充 locked test。
6. 只改金标或评分器而实际模型输入未变：保留预测身份，生成新评分版本；改 question/context/system/template/推理参数：重新审输入并重新推理。不要因为 case_id 相同就命中缓存。

验收：A/B 具备真实执行器、协议冻结记录、逐条预测、逐条教师评估、计划分母、覆盖率、失败和分歧记录。报告不依赖手工填写的汇总数字。

### P1 / M3：依据诊断结果开展可控训练

训练前先给出诊断结论和选择依据：

- 若主要问题是规则误判或候选金标不合理，先修审核与评测，不用训练掩盖测量错误。
- 若 A 显示问法鲁棒性不足，优先设计表达覆盖的数据干预；其训练材料只能来自训练来源，不能使用 A/B/dev 评测题本身。
- 若 B 显示证据边界处理错误，设计普通 SFT 对照与加入行为样本的单因素对照。
- 若独立来源简单题存在天花板，在 dev 构造条件、否定、数值绑定、多证据等难题；冻结选题规则，保留原简单题作锚定，不根据某模型输出挑有利题。

新实验要求：

1. 建立新的可复现 G0：统一 base revision、tokenizer、chat template、精度、LoRA 参数、优化器、最大长度及数据版本；旧 adapter 仅供历史诊断。
2. 先完成单 seed 小试，验证训练数据实际被使用、assistant token mask 正确、无空目标和静默截断，再在预算具备时运行至少 3 个配对 seed。只有 1 个 seed 时必须标为 pilot，不能宣称稳定改进。

4. 记录实际采样 ID、样本权重是否被 sampler/loss 真正消费、有效目标 token、global_step、训练时长、显存峰值和最终 adapter 哈希。仅有配置字段不算干预落地。
5. 在相同冻结协议上做 base/G0/干预模型对比，单独报告质量、行为、保留能力及成本，不只报告训练 loss。

## 四、教师模型替代人工审核的技术方案

### 4.1 分开三类工作，避免循环自证

| 工作 | 输入 | 输出 | 约束 |
| --- | --- | --- | --- |
| 训练数据审核 | 最终问题、学生可见上下文、最终 assistant 目标、来源证据、任务模式 | 内容与行为是否合格、证据定位、修订/隔离原因 | 保留已有确定性过滤和最终哈希；教师通过不能覆盖结构失败 |
| 评测协议审核 | 题干、可见上下文、候选参考答案/要点、expected_action、条件变换 | 可冻结的机器审核参考版本及其证据 | 审核时不展示 base/adapter 回答，防止按学生答案反向改金标 |
| 回答效果评估 | 冻结后的题目/可见上下文/审核参考，匿名学生回答 | 任务完成、行为适当、证据支持、错误标签 | 不透露模型身份或微调前后标签；评估版本与预测版本分离 |

对 rag_grounded，裁判必须按学生实际可见的完整上下文判定可答性。来源原文可用于追溯候选事实，但其中隐藏的信息不得被当作学生可用支持。closed_book_domain 单独使用对应 rubric 和外部参考证据，不能套用“所有答案必须由可见上下文支持”的标准。

### 4.2 审核后端与兼容方式

建议新增 reviewing/ 包，包含 schemas.py、service.py、policy.py、teacher.py、cache.py 和 prompts/，或采用等价但统一的目录结构。

- ReviewBackend：统一 review_gold、review_training_sample、review_answer；实现 human、teacher、hybrid。human 适配原 review_io，不改写其历史语义。
- review_mode=teacher_only 为本轮实验配置；旧配置默认保持兼容，不自动转换历史记录。
- reviewer_role 区分 generator、gold_reviewer、answer_judge、arbiter；模型提供方、精确 model/revision、prompt_version、rubric_version 独立配置。
- 优先使用与生成器不同的强模型作审核，第二裁判尽量使用不同模型族。两个端点或两个名字不等于独立模型；必须记录真实身份和 independence_level。
- 只有一个模型可用时可配置 single 模式，标记 teacher_single_accepted、uncalibrated，报告自评偏差；不能把重复调用包装成双模型共识。需要双审的高风险项在第二裁判缺失时保持隔离，其他低风险探索工作可以继续。

### 4.3 结构化审核记录

至少实现以下类型；使用 Pydantic 严格校验，禁止靠自由文本中的“通过”判断。

ReviewRecord：
- review_id、batch_id、subject_type（training_sample/protocol_case/prediction）、subject_id、subject_version。
- review_source（human/teacher/hybrid）、review_mode、review_policy_id、policy_version。
- subject_hash、model_input_hash、evidence_snapshot_hash、gold_hash（不适用可为 null）。
- provider_id、model_id、model_revision、model_identity_verified、prompt_hash、rubric_version、inference_config_hash。
- decision（accept/revise/reject/abstain），execution_status（succeeded/technical_failed/budget_stopped/cancelled），独立存储。
- dimensions：question_clear、semantic_preserved、evidence_adequate、factual_consistency、required_points_complete、behavior_appropriate、no_unsupported_claims。
- claims[]：claim_id、claim_text、status（supported/contradicted/insufficient）、visible_evidence_refs[]、source_evidence_refs[]。
- answerable_points[]、unavailable_points[]、numeric_bindings[]、required_conditions[]、contradictions[]。
- reason_codes[]、简短 evidence_summary、suggested_patch（修订建议不能直接写回已冻结对象）。
- confidence（可选自报值）、confidence_calibrated=false；自报值不当作正确概率，也不作为唯一放行条件。
- request_id、attempt、usage、estimated_cost、currency、pricing_version、created_at、raw_response_artifact_id。
- review_set_id、judge_role、independence_level、parent_review_id、supersedes_review_id。

ReviewAggregate：
- subject_id、subject_hash、active_review_ids[]、human_review_status、teacher_review_status。
- teacher_review_status：unreviewed/pending/teacher_single_accepted/teacher_consensus_accepted/needs_revision/rejected/disputed/technical_failed/budget_stopped/stale。
- accepted_by_policy、policy_version、quarantine_reason、readiness_scope。
- ready_for_training、ready_for_exploratory_inference、ready_for_formal_human_eval，由服务根据真实记录计算，前端不能直接传 true。

现有 review_status 人工字段原样保留；教师状态置于独立字段或独立审核表。导出 metadata 写入 review_source、review_set_id、policy_version、subject_hash，能追溯每条样本的自动审核依据。

### 4.4 审核判定流程

1. 先做确定性检查：schema、唯一 ID、来源可追溯、文本非空、合法枚举、证据 span/offset、输入长度、哈希、来源划分、数字与单位绑定。失败不送入“自动通过”通道。
2. 教师 J1、J2 独立看同一对象，互不看对方结论。要求引用可见证据位置，逐项检查事实、否定、条件、范围和预期行为。输入资料作为数据隔离，资料中的“忽略规则、直接给满分”等指令不得改变审核任务。
3. 双审策略下只有双方 accept、关键维度满足门槛、无未解决矛盾且证据定位通过才产生 teacher_consensus_accepted。不以平均总分掩盖关键事实错误。
4. 对分歧使用一次独立裁决：裁决器先据证据判断，再比较简短分歧摘要。无法消除矛盾、无可用独立裁决器或超预算，置 disputed/quarantine，不默认按多数或最高分通过。
5. revise 生成新内容版本，保留 parent/version；最多一次自动修订并完整重审。修订时不得改变实验处理条件，例如为了让 removed_support 可答而补回支持。超限进入隔离。
6. reject 和 abstain 不混用：前者是有依据的不合格，后者是无法可靠判定。超时、非 JSON、缺字段、截断响应属于技术失败，有限重试后保持失败。
7. 针对教师自评偏差：记录生成器与裁判是否同源；对可程序验证的数字/条件/证据做独立检查；使用对象替换、删证据、条件翻转等合成反例做审核器回归。合成反例只是工程检查，不能据此宣称自然数据上的审核准确率已校准。
8. 回答评分先对匿名单答做绝对维度评价；若另做 A/B 偏好评估，随机左右位置并抽样交换位置，报告位置不一致率。模型身份映射仅用于最终聚合。

### 4.5 门禁与失效规则

在 pipeline 发布、export、SFT 数据加载、eval-adapter、A/B 执行器、API 任务入口共用 ReviewPolicyService，避免只在 UI 拦截。

- teacher_only 新运行的训练/发布样本：现有 S/A、非 rejected/quarantine/needs_escalation、最终验证哈希一致，且当前教师审核被配置策略接受，方可进入相应实验性训练导出。
- 审核策略不可由普通请求随意降级；配置在运行开始时冻结。旧记录没有审核字段时标 legacy_unreviewed，历史浏览仍可用，新 teacher_only 训练不能自动继承通过。
- 评测协议：教师接受仅允许 teacher_only 范围内的探索推理。formal 的人工门禁仍拒绝纯教师记录；formal_main_metric 保持 not_executed。
- case 输入变化使教师金标审核和预测均失效；gold/rubric 改变使相关审核/评分失效，输入不变时预测可复用；模型/模板/推理参数变化使预测失效。
- 审核依赖实际内容、策略、模型、模板和证据版本；不能通过重填哈希或改状态来迁移。
- 正式协议无效整批停止的现有规则不变。新的 A/B teacher_only 批次也要求完整组就绪；不能利用 exploratory 原来较宽松的验证绕过本轮审核政策。
- 不回写既有人工审核 CSV，不将模型名写入“人类审核者”字段。保留原 import-review CLI，新增独立 teacher-review 与审计读取入口。

### 4.6 运行可靠性与落盘

- 复用 LLMClient 的用量与错误结构；增加并发限流、请求超时、有限指数退避、调用/token 硬预算和在途请求预算预留。失败和重试也记入账本。
- 缓存键至少覆盖 subject_hash、review_kind、实际模型 revision、prompt/rubric/policy 版本、推理配置及 evidence_snapshot_hash。未知 revision 明确记录，并通过配置版本控制失效。
- append-only 保存 reviews.jsonl、review_aggregates.jsonl、review_events.jsonl、usage.jsonl、policy_snapshot.json、prompt_manifest.json；失败可恢复但不能重复裁定或重复计费汇总。
- 单样本提交原子化；中断恢复只跳过已提交且签名匹配的审核，半条记录不得视为成功。重跑产生新 attempt，保留旧记录。

### 5.2 分层与接口

保留已有模块，逐步形成：

- 核心层：通用数据 schema、Pipeline、策略注册、审核政策、来源划分、评测身份与缓存。
- 适配层：DocumentParser、SourceFamilyResolver、ModelProvider、TrainingBackend、ArtifactStore、Exporter。
- 领域扩展层：DomainProfile、DomainValidator、TaskTemplate、EvidenceTransform；默认 generic，可选 drug_instructions、psychiatry。
- 应用层：运行编排、审核服务、数据集服务、训练/评测服务、问答服务。
- 表现层：CLI 与 FastAPI 共用应用服务，前端不包含算法或业务放行规则。

避免强制把所有文件迁入新目录。先抽出真实复用边界，保留旧 import/CLI 兼容壳；新增插件要注册并加入 plugins/__init__.py 加载列表。

DomainProfile 至少描述 domain_id、language、entity_schema、family_key_strategy、任务模板集合、扩展校验器、单位/数值规则和 rubric 扩展；不能改变核心字段语义。通用流程不得根据 recipe 名字包含 drug 等字符串分支。

### 5.3 数据输入、来源和划分

- 首期稳定支持 Markdown/TXT；JSON/JSONL 通过显式字段映射解析；PDF/DOCX 作为可选解析插件，未实现时返回 unsupported_format，不能伪装为读取成功。
- Document 保存原文哈希、规范化哈希、source_uri/source_id、解析器版本、语言、来源版本、许可证/可用范围（若已知）。未知信息不猜填。
- SourceFamilyResolver 支持用户提供映射、文档元数据规则和默认归并策略。文件名或单一内容哈希不足以证明来源独立；修订版、近重复、同一实体资料需在切分前成组。
- 在来源族级别冻结 train/dev/locked_test。所有改写、行为变体、派生 QA 继承 lineage；多来源和干扰材料的所有来源族都参与泄漏检查，不仅检查主文档。
- generic 行为转换覆盖空上下文、移除支持、错误对象、保留支持加干扰、缺条件、部分可答、对象歧义；转换结果依旧需要审核，不能靠模板名称断言成立。
- 分清任务模式与检索系统：rag_grounded 表示给定资料回答，并不表示项目已经有完整 RAG 检索。检索器可作为后续适配器扩展。

### 5.4 通用性验收

至少准备三类小型可公开 fixture：设备/软件使用说明、业务流程/政策说明、百科或产品规格。另保留药品历史 fixture 作为兼容回归。

同一条 CLI/API 路径、同一核心 schema 和 generic profile 能完成三类文档的解析→生成→审核→导出；不修改核心代码，不出现无关的药品话术。验证数字、否定、条件、表格、跨段和无标题正文等输入。

这只能证明工程接入通用性；若要声称跨领域模型效果提升，需要另行建立来源隔离的真实跨领域评测，不能将 fixture 跑通等同泛化验证。

### 6.3 统计口径

- qa 保留率=accepted/raw；发布率=released/accepted；审核覆盖率=有有效裁定的对象/planned；共识率的分母必须写明为双审完成对象。
- 不把 accepted、exported、consumed、eval case、prediction 混成一条“样本数”。
- 效果指标同时返回 name、value、numerator、denominator、unit、metric_role、review_source、result_class、missing_reason、confidence_interval/method、scorer_version。
- planned_n 固定，失败/未决不静默删除。可报告有判定样本上的条件通过率 P/S，同时展示 S/N 覆盖率；另给 P/N 至 (P+N−S)/N 的未决上下界并明确不是语义正确率。技术失败单列，不直接计为内容错误。
- A 按核心问题、来源族聚合，三种问法不算三份独立证据；B 报告四条件分别结果、成组一致率、充分证据的过度拒答率、不足/错对象条件的无依据作答率、干扰下退化。
- 前后对比对齐同一 case 与实际输入；使用来源族聚类的配对区间。多 seed 额外报告 seed 间变化，不把多 seed × 多改写当作独立样本数。
- 教师评分和规则评分分开展示；nli_mean/judge_mean 未执行为 null + reason，不为填仪表盘而临时调用模型。

| 配置与运行环境 /settings | 可用 provider/model、领域 profile、recipe、审核政策、价格版本；只显示配置状态不显示密钥 | capabilities、recipes、profiles、policies、provider status | P2；P1 提供只读必要项 |

### 7.3 交互与真实性要求

- 全流程首期展示“实际发生的 DAG/阶段链”，不做拖拽工作流编辑器。未执行、跳过、失败、预算停止、缓存复用分别显示。
- 样本页以“学生可见资料”和“原始来源证据”分栏，防止把隐藏信息误解为学生输入；突出最终训练 messages 和审核绑定的内容版本。
- 审核页显示 review_source=teacher，并展示单模型/双模型/同族模型关系；不能用“人工已审核”“金标准确率”标签。
- 效果页的默认对比必须同协议、同输入、同解码条件；条件不匹配时标不可直接比较。分别展示 train_seen、seen_rephrase、dev_independent、behavior、locked_test，默认不计算混合总分。
- 问答 Demo 首期支持用户提供上下文或选取已登记资料；如无检索器，不展示“自动检索”按钮。双模型使用同一份已固定上下文、system 与生成预算；关闭共享检索重复运行导致的输入差异。
- 在线问答是实时演示，不写入冻结评测集或训练集。可收藏为待审核候选，但必须另建版本并审核。
- 模型不可用时显示 unavailable/配置原因；不能返回 fake 答案冒充线上模型。fake 演示需要显眼标记。
- 每页具有 loading/empty/partial/missing_artifacts/failed/cancelled 状态；旧产物不完整时可看已有数据，不生成虚构图表。
- 列表后端分页，较长正文/完整证据按需加载；全文详情不能只返回截断 clip。Markdown/HTML 安全渲染，不直接将模型文本塞入 innerHTML。

## 八、后端接口清单与工程契约

### 8.2 公共规范

- 成功响应：{data, meta:{request_id,schema_version,next_cursor,total,as_of}}；错误：{error:{code,message,details,retryable},request_id}。统计里的 null 与 0 不同。
- 列表使用稳定 cursor + limit（默认 20，最大 100），支持声明过的筛选/排序；禁止每次把整个 JSONL 读入内存再分页。
- 长任务 POST 返回 202 + job_id/resource_id；同步校验不通过返回 422/409。创建任务支持 Idempotency-Key，重复请求不能重复跑模型。
- 409 用于版本冲突/未就绪/协议不匹配，404 为对象缺失，429 为限流；服务端资源不可用使用明确错误码。技术失败不返回空成功列表。
- 时间统一 ISO 8601 UTC，前端按用户时区展示；ID 不直接映射用户提供的任意路径。
- API OpenAPI schema 作为字段唯一契约。可生成前端类型或校验器；保留旧接口的适配测试。

### 8.4 服务运行与存储

- JSONL/manifest 继续作为可追溯事实来源；增加 SQLite 元数据/索引用于分页、查询、job 状态与事件序号，可从产物重建。先保持单机部署，不提前引入多服务集群。
- API、worker、模型服务分离生命周期。GPU 任务在独立 worker/进程执行，不放在 HTTP 请求或易丢失的 FastAPI BackgroundTasks 内；同 GPU 调度有资源锁与上限。
- 任务状态 queued/running/succeeded/failed/cancelled/blocked；中断通过 heartbeat 识别，不把上次 running 自动标 succeeded。只恢复已校验产物。
- SSE 基于持久事件序号续传，支持断线重连与重复事件去重；取消以检查点协作执行，记录已发生用量。
- 配置服务器端允许的 artifact/model/provider ID，不让浏览器传任意磁盘路径、URL 或 shell 命令。访问根目录内的 resolve 检查也要防符号链接越界。
- 默认本地监听；对外提供服务时加入认证及项目级资源授权、CORS 白名单、上传大小限制和调用限流。教师与学生 API key 只保存在服务端。
- 运行报告和 UI 使用脱敏 provider 名称；敏感完整提示词/响应仅按权限读取。模型评委没有工具执行权限。

## 十、验收标准与必要测试

### 10.1 必须自动验证的风险

1. 缺字段、非法 JSON、超时、预算停止、裁判 abstain 均不通过审核，且错误类型不混同内容拒绝。
2. 双审分歧、同模型伪装双模型、缺证据和关键条件矛盾不能产生 teacher_consensus_accepted。
3. question/context/system/answer 任一变化触发对应审核/预测/评分失效；仅改金标时不错误重用旧评分，也不无谓重跑输入相同的预测。
4. 教师记录不能通过原 formal 人工审核门禁；原人工 CSV 的空白、machine_reviewer、哈希错误检查仍有效。
5. 隔离/B 级/待修订/审核过期样本从 CLI、API、export、SFT 任何入口均不能绕过新运行的发布政策。
6. 来源族、多来源干扰材料、样本派生关系均参与 split/泄漏检查；空清单不能作为“无重叠”的证据。
7. 预算在并发和重试下不失控；中断恢复不重复提交有效裁定；取消与失败不伪造完成事件。
8. 所有过滤处置留痕且计数可核对；历史缺失项显示未知，不凭集合差生成假理由。
9. A/B 全批未就绪时不加载模型；准备函数就绪与实际执行完成明确区分；缓存复用遵守完整身份。
10. API 分页/版本冲突/权限/路径约束、事件重连、上传限制及模型不可用状态正确。
11. 页面能从运行节点追到样本和原文，能查看同题前后回答；chat 双模型同输入、流式输出、单边失败和取消均能正确显示。
12. generic profile 在至少三类非医疗 fixture 上走通，不出现领域词汇泄漏；旧药品入口保持可用。

沿用相关现有测试：test_pipeline.py、test_contracts.py、test_review_io.py、test_adapter_eval.py、test_eval_reliability.py、test_v25_prepare.py、test_demo.py。为新增审核、事件/恢复、通用输入和 API 契约补充针对性测试。最终行为变更运行完整 pytest；不增加只复述实现或文档的低价值测试。

### 10.2 每个里程碑的交付物

| 里程碑 | 可核验交付物 | 通过条件 |
| --- | --- | --- |
| M0 | state_snapshot.json、资产 manifest、基线测试结果、缺失项列表 | 当前阶段和接续条件可追溯 |
| M1 | 教师审核服务、策略/提示词版本、FakeLLM 回归、小批真实审核（资源可用时） | 无人工代填、失败不放行、预算/缓存有效 |
| M2 | batch1/A/B 新协议、预测、自动评分、覆盖率/分歧/失败报告 | 已执行与未执行分开，分母完整，旧资产不变 |
| M3 | 新训练对照协议、训练 manifest、adapter、同协议前后结果 | 训练条件可比；单 seed 和多 seed 结论范围明确 |
| M4 | 流程/数据集/评测/问答页面、/api/v1、运行说明 | 四项用户需求均有真实数据路径，资源缺失时状态可信 |
| M5 | 通用 profile、三领域 fixture、兼容/泄漏测试和扩展文档 | 新领域接入无需改核心，领域无关 API 可复用 |

M4/M5 可与 M2/M3 交错推进；它们不以昂贵训练完成作为开始条件。主依赖为 M0→M1→M2→是否需要 M3；事件/契约是 M4 的前置，核心领域解耦从 M1 同步进行。

## 十一、Cursor 的具体执行顺序与交付形式

按以下变更批次实施，每批保持可运行并给出简短进展：

1. 审计与基线：完成 M0，报告当前 HEAD 与本计划基线的差异，给出阻塞矩阵。
2. 契约与通用门禁：增加 review schema/policy、配置解析和核心领域解耦；保留 human/旧接口兼容。
3. 教师审核运行器：FakeLLM 测试通过后，在已配置预算内执行 batch1；缺真实资源则交付 dry-run 和具体阻塞，不假造结论。
4. 接续实验执行器：补齐 B、A 的冻结/就绪/缓存/真实推理/自动评分/聚合流程。
5. 中间产物与 API：落盘事件、索引、运行/审核/评测只读 API，之后启用持久任务写接口。
6. 前端：先流程与样本追溯、数据集信息，再效果对比和在线问答，最后补配置/任务管理。
7. 依据已得到的诊断运行新训练对照，验证训练干预真实生效。
8. 完成三类非医疗接入与回归，更新现有文档，给出最终完成/阻塞列表。

建议新增 CLI（实现前不要声称能直接执行）：

- qa-pipeline audit-state：只读输出当前资产与阶段。
- qa-pipeline teacher-review：指定 subject manifest、policy、models、budget、out，支持 dry-run/resume。
- qa-pipeline run-reviewed-eval：读取已冻结协议、执行教师审核政策门禁，再调用已有 eval-adapter 服务。
- qa-pipeline index-runs：从运行产物建立/重建查询索引。
- qa-pipeline serve：启动通用工作台；原 demo 入口保持兼容。

具体参数以实现后的 --help 和 OpenAPI 为准。配置中的策略参数继续与 name 同级，不嵌套 params。

每批完成时输出：

- 已改文件与对应目标。
- 真正执行的命令、测试 passed/failed/skipped；未执行的真实任务及资源原因。
- 新增产物路径、哈希和状态；本轮代码 commit/config/prompt/policy/protocol 版本。
- 若有指标，说明计划分母、有效分母、失败/未决、自动审核来源及结论边界。
- 下一项可直接执行的动作；不得用“代码已完成”替代“实验已执行”。

在既有授权和资源范围内持续完成计划，不反复询问是否继续。仅当真实运行缺不可推断的配置/资产，或需要改变实验目标、扩大明确预算时提出具体问题；同时继续可独立完成的工程工作。
